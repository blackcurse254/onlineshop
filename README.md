# VERA BOUTIQUE — فروشگاه تخصصی کفش و کتونی (RTL / PostgreSQL / Express / React)

یک فروشگاه اینترنتی تخصصی کفش، کتونی، کفش ورزشی، روزمره و رسمی با طراحی تجاری قابل شخصی‌سازی (White-Label)، زبان فارسی راست‌چین (RTL)، مدیریت موجودی مستقل برای هر سایز کفش و معماری امن سمت سرور.

## ویژگی‌های کلیدی

- **دامنه تخصصی کفش و کتونی**: ۱۰ دسته‌بندی تخصصی (کتونی مردانه، کتونی زنانه، کفش اسپرت، روزمره، پیاده‌روی، ورزشی، رسمی، صندل و دمپایی، بچگانه و لوازم جانبی کفش) به همراه برندها و مشخصات فنی کفش (جنس رویه، جنس زیره، ویژگی‌ها و نگهداری).
- **موجودی مستقل برای هر سایز (`sizeInventory`)**: انتخاب هر سایز در صفحه محصول با نمایش موجودی دقیق همان سایز و غیرفعال‌شدن خودکار سایزهای ناموجود.
- **ثبت سفارش اتمیک در دیتابیس**: تراکنش PostgreSQL با قفل‌گذاری ردیف (`SELECT ... FOR UPDATE`)، محاسبه قیمت و تخفیف در سرور و کسر دقیق موجودی سایز انتخاب‌شده بدون امکان فروش مازاد هم‌زمان.
- **راهنمای سایز و بزرگنمایی تصویر**: جدول تطبیق سایز EU/CM/UK/US و مودال بزرگنمایی تصاویر محصول.
- **لیست علاقه‌مندی‌ها و نظرات مشتریان**: پشتیبانی از Wishlist برای کاربران مهمان و اعضا و بخش ثبت و تایید نظرات خریداران.
- **پنل مدیریت White-Label**: مدیریت محصولات و ماتریس موجودی سایزها، آپلود امن تصویر (محدودیت ۲ مگابایت + بررسی Magic Bytes برای JPG/PNG/WEBP)، مدیریت دسته‌بندی‌ها (افزودن/ویرایش/مرتب‌سازی/حذف)، برندها، سفارش‌ها، تخفیف‌ها، بنرها و تنظیمات ظاهری برند.
- **پرداخت نمایشی (Demo Checkout)**: پرداخت در این نسخه به‌صورت آزمایشی شبیه‌سازی شده و هیچ درگاه بانکی واقعی متصل نیست.

## پیش‌نیازها و نصب

1. نصب وابستگی‌ها:
   ```bash
   npm install
   ```
2. کپی فایل نمونه متغیرهای محیطی و تکمیل مقادیر در `.env`:
   ```bash
   cp .env.example .env
   ```
   متغیرهای مهم امنیتی:
   - `SESSION_SECRET`: رشته تصادفی حداقل ۳۲ کاراکتری (در حالت `production` اجباری است؛ در صورت نبود آن، سرور اجرا نمی‌شود).
   - `INITIAL_ADMIN_EMAIL` و `INITIAL_ADMIN_PASSWORD`: ایمیل و رمز عبور قوی (حداقل ۱۲ کاراکتر) برای ایجاد حساب مدیر اولیه هنگام راه‌اندازی.
   - `PGHOST`، `PGPORT`، `PGDATABASE`، `PGUSER`، `PGPASSWORD` (یا اتصال Cloud SQL).

3. اعمال اسکیمای PostgreSQL با Drizzle:
   ```bash
   npx drizzle-kit push --config=src/db/drizzle.config.ts
   ```

4. اجرای محیط توسعه یا ساخت نسخه نهایی:
   ```bash
   npm run dev
   # یا برای بیلد و اجرا:
   npm run build
   npm start
   ```

## توصیه‌های امنیتی پس از عمومی‌شدن مخزن

اگر مخزن گیت‌هاب پروژه به‌صورت عمومی (Public) منتشر شده است:
1. هرگز فایل `.env` یا کلیدهای محرمانه (`SESSION_SECRET`, `PGPASSWORD`, رمزهای ادمین، یا Service Account JSON) را در گیت کامیت نکنید. اگر قبلاً چنین مقادیری در تاریخچه گیت قرار گرفته‌اند، فوراً آن‌ها را **Rotate** (تغییر/تولید مجدد) کنید.
2. فایل `firebase-applet-config.json` شامل تنظیمات عمومی کلاینت Firebase Web SDK است؛ برای جلوگیری از سوءاستفاده احتمالی، در **Google Cloud Console → APIs & Services → Credentials** بر روی Web API Key محدودیت دامنه (**HTTP Referrer Restrictions**) اعمال کنید.
3. در محیط عملیاتی (`NODE_ENV=production`) حتماً `APP_URL` و `SESSION_SECRET` معتبر تنظیم کنید تا بررسی CSRF Origin، کوکی `Secure` و محدودیت CORS به‌درستی فعال بمانند.
